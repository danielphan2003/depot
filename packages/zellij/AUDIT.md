## 0.46.1-1 (2026-11-24)

- **Why depot ships it:** Daniel's nushell starts inside zellij; Arch ships it, Debian 13 and Fedora 44 do not. Upstream's static musl release binary, as for 0.46.0, because Debian 13's Rust is too old to build it and Fedora 44 does not ship it.
- **Source:** `zellij-x86_64-unknown-linux-musl.tar.gz` from the HTTPS GitHub release of `zellij-org/zellij`. The archive's pinned sha256 in `package.env`, `1633211357c236053b51d1ae6415c23f7ff71aaae8e087315e499ceca1b17fa4`, matches the archive I downloaded and GitHub's v0.46.1 release asset digest (uploaded by `github-actions[bot]` on 2026-11-24). The archive holds one file, `zellij`, mode 0755, 84024976 bytes, a stripped static-pie ELF with no interpreter and no `NEEDED` entries. Upstream's `zellij-x86_64-unknown-linux-musl.sha256sum` gives `9310e14d31621ff23fc14bed2244e348f72bafe6c75f2871825d0f4708fb6ce7` for `target/x86_64-unknown-linux-musl/release/zellij`, which is the hash of the binary in the archive. As for 0.46.0: the annotated tag `v0.46.1` and its commit `af1cb35679f933382fd846325babe1a080508c5c` are unsigned, the checksum file is not signed, and GitHub holds no artifact attestation for the asset (the attestation lookup answers 404). The pinned hash and GitHub's recorded asset digest are the provenance depot has.
- **Dependencies:** depot adds none; the recipe resolves no crates. Upstream's `Cargo.lock` adds eight crates and drops three. winit's new `wayland-csd-adwaita` feature brings `sctk-adwaita`, `tiny-skia`, `tiny-skia-path`, `ab_glyph`, `ab_glyph_rasterizer`, `owned_ttf_parser`, `strict-num` and `arrayref` from crates.io (the winit/Smithay and font-rendering maintainers), and `atty`, `getopts` and `pretty-bytes` leave. None of this enters depot's build, which repackages the release binary.
- **Build:** none in depot. The Debian and RPM recipes unpack the pinned archive and install the upstream binary as-is; there are no extra downloads, compiler flags or generated source in the depot build. Upstream's release workflow changed: it now also publishes GNU/glibc x86_64 and aarch64 assets, cross-built with zig 0.17.0 (a sha256-pinned download in CI) and cargo-zigbuild, and checked by a new `.github/scripts/check-gnu-binary.sh` for glibc 2.17 and base libraries only. The musl jobs that produce the asset depot pins are unchanged, and depot uses no gnu asset.
- **Install:** no install scripts, units, links, or special permissions. The recipes install the plain executable at `/usr/bin/zellij`; Debian's documentation files are plain files in the allowed documentation directory. No new install path or `allow` exception is needed.
- **Upstream change:** I read the linked `v0.46.0...v0.46.1` diff, 43 commits and 202 files, rather than the changelog. It adds `zellij events`, a CLI subscription that streams JSON session events over the local session socket, with its filter types in `zellij-utils/src/session_events.rs`. Desktop-app work adds macOS Dock and "Open With" handling, pasting the path of a dropped file, Cmd+click links (opened through the existing `xdg-open` action), window reuse fixes and a Wayland exit segfault fix. The terminal gained fontconfig-based font discovery that filters unsupported fonts (system fontconfig only, skipped in static builds), clipboard and keyboard handling fixes including non-Latin layouts, and `ZELLIJ_SESSION_ID` in the pane environment. The web client fixes paste and hardware-keyboard handling on touch devices; `integrity.json` is updated for the new `app.js`, and the changed built-in `.wasm` plugins are rebuilt from their in-repository Rust sources. No telemetry or automatic reporting, no new network endpoint, no new credential handling (the existing attach token is only threaded through the new launch paths), and no vendored binary beyond the rebuilt plugins. The added sponsor logo is a README asset.
- **Upstream status:** active, same `zellij-org` project; v0.46.1 was published 2026-11-24.

## 0.46.0-1 (2026-11-13)

- **Why depot ships it:** Daniel's nushell starts inside zellij; Arch ships it, Debian 13 and Fedora 44 do not.
- **Why a binary:** Daniel's standing decision is to repackage upstream's release binaries, and build from source only when needed. Debian 13 has Rust 1.85 while zellij 0.46 requires 1.95, and Fedora 44 does not ship zellij. Upstream publishes a static musl build.
- **Source:** `zellij-x86_64-unknown-linux-musl.tar.gz` from the HTTPS GitHub release of `zellij-org/zellij`. The archive's pinned sha256 in `package.env`, `a8ee599eb357b6142443c91506a4ece3aa8811cb75dcf2b28d194bd66853c79d`, matches GitHub's v0.46.0 release asset digest. Upstream's `zellij-x86_64-unknown-linux-musl.sha256sum` covers the binary inside; its `afb6bfb5f9fdc3d9e9d094ce21866bc99d37073a5fbe75bb612e21fc9b96033d` matches the binary streamed from the archive. The tag is unsigned, and I found no detached signature or GitHub artifact attestation; the checksum file is not signed.
- **Dependencies:** Depot adds no build dependencies. The recipe does not resolve crates or other dependencies. Upstream's source adds Cargo dependencies for its desktop terminal and pins them in `Cargo.lock` from crates.io; the depot recipe repackages the release binary rather than building those sources.
- **Build:** none in depot. The Debian and RPM recipes unpack the pinned archive and install the upstream binary as-is; there are no extra downloads, compiler flags, or generated source in the depot build.
- **Install:** no install scripts, units, links, or special permissions. The recipes install the plain executable at `/usr/bin/zellij`; Debian's documentation files are also plain files in the allowed documentation directory. No new install path or `allow` exception is needed.
- **Upstream change:** Read the linked `v0.45.1...v0.46.0` diff, including its build/workflow changes. It adds the desktop terminal, inbox/attention features, configuration UI and fixes. The changed `.wasm` built-in plugins are generated from their in-repository Rust plugin sources by upstream's xtask. New desktop-terminal font files are identifiable Iosevka, Noto and Nerd Fonts assets with accompanying license texts; the added manual regeneration script fetches those assets from their named publishers over HTTPS, but it is not used by depot's recipe. The release workflow now downloads protoc 23.4 from the official Protocol Buffers GitHub release; this is upstream CI only. The new integrations reference is a link opened only when the user clicks it. No telemetry or automatic reporting was found. A new `dangerously_allow_web_serving_without_a_certificate` option permits remote plain HTTP only when explicitly enabled; it defaults off, tests keep remote HTTP refused by default, and the server warns that login tokens are unencrypted when enabled.
- **Upstream status:** active, same `zellij-org` project; v0.46.0 was published 2026-11-11.
